# Почати з ICE 0.8.4

Використовуйте **всю поточну папку ICE**, зберігаючи структуру каталогів. Виправлення 0.8.4 внесено безпосередньо до цієї локальної папки. Відкрийте термінал там, де лежить `run.sh`.

```bash
bash run.sh
```

Початкова сторінка — **index.html**. У бічній панелі має бути версія **0.8.4**
та логотип Житомирського агротехнічного фахового коледжу. Якщо бачите 0.7,
відкрито старі файли: не запускайте стару копію й не використовуйте Drive preview.

Заповнені розділи 1–2 запускають розрахунок автоматично. Початковий розрахунок
може зайняти кілька секунд. Після редагування дочекайтеся повідомлення
«Перераховано». Червона помилка означає, що актуальний експорт заблоковано.
Вибір класу зберігає власні введені значення; для повернення початкового використайте кнопку біля поля. Непотрібні розділи сірі. Основні діаграми ДВЗ — 0–720° для чотиритактного або 0–360° для двотактного режиму. Двотактний режим задає окремі вікна продувки/випуску й тиск продувки; це навчальна модель без розрахунку нагнітача.

Готові PDF початкового варіанта: `build/design-report.pdf`,
`build/methodical-guide.pdf`, `build/A1-design.pdf`. Кнопки в інтерфейсі
формують нові публікації для актуального стану. Для збереження виберіть PDF
у системному діалозі друку. Для подальшої роботи збережіть JSON свого варіанта.

Node.js >=22.16 потрібен для run.sh. npm install не потрібен.
Для автоматичної генерації PDF потрібен Chrome/Chromium.
Зупинка сервера — Ctrl+C. `bash run.sh --diagnose` нічого не змінює.
Після редагування вихідних фрагментів використайте `bash run.sh --rebuild`.

Чисельні, фізичні й браузерні межі — у README та DELIVERY-v0.8.md.
Довгий браузерний stress-тест ще не підтверджений; не плутайте це з
перевіреними окремими операціями або експериментальною точністю моделі.


## Виправлення 0.8.4 — 2 жовтня 2026

Рисунок 8.1 має додатковий простір над найвищою точкою та винесені підписи А / Б / В із короткими лініями до відповідних точок. Підписи вказують вантаж або батарею; їхні межі перевірено для 200 та 350 кг. Числові результати й рисунок 7.2 збережено.

Праворуч у вступі — емблема кафедри автомобільного транспорту з TEA/New. Вона обертається перетягуванням або стрілками; плюс/мінус змінюють масштаб. Статичний PNG працює, коли 3D недоступне.

Поруч із I-174 розміщено таблицю початкових вантажів і приблизної номінальної вантажності M1–N3. Це проєктні орієнтири з адаптації Automobile, а не нормативна вантажність кожної категорії. Ручний вантаж зберігається при зміні категорії.

Розділ **8.6. Узгодити батарею, вантаж і потрібний пробіг** порівнює три способи оцінки меж. В українському інтерфейсі це А, Б, В (A, B, C):

- **А:** поточна батарея + потрібна відстань → найбільший перевірений вантаж. Кнопка приймає цей вантаж зі збереженням батареї.
- **Б:** заданий вантаж → найбільша перевірена батарея та її максимальний пробіг. Кнопка приймає батарею зі збереженням вантажу.
- **В:** поточна батарея + заданий вантаж → максимальний пробіг поточної пари.

Обидві кнопки зберігають ціль I-166, маршрут, резерв заряду, компоненти та базу без батареї. Батарея фіксується в режимі заданої енергії; повна маса перераховується. Скасування — у розділі 2. Якщо значення вже збігається з відповідною межею, повторне прийняття вимкнене. Відсутність допустимого А не приховує незалежні оцінки Б і В.

Порівняльна таблиця показує зафіксовані величини, результати й обмеження. Рисунок 8.1 має однакові вертикальні шкали в кг: помаранчева крива змінює вантаж із поточною батареєю, синя змінює батарею із заданим вантажем. Зелена горизонталь і фіолетова вертикаль підписані введеними вимогами. Позначки А і Б належать відповідним кривим, В показує поточну пару. Перетин кривих не визначає оптимум: порівнюються різні маси.

Для **101 кВт·год / 350 кг / 250 км**, бази 1400 кг і повної маси до 2600 кг:

- А: **365 кг**, **101 кВт·год / 631,25 кг**, пробіг **250,03 км**.
- Б: **136 кВт·год / 850 кг**, **350 кг**, пробіг **322,14 км**. Тут обмежує повна маса.
- В: **101 кВт·год / 631,25 кг**, **350 кг**, пробіг **250,88 км**.

Це розрахунок до заданого резерву заряду. Межі визначають маса й тяга; Б також обмежено діапазоном енергії моделі. Обидві варіації мають окремі CSV `*-payload-fixed.csv` і `*-battery-fixed-payload.csv`; `*-battery-choices.json` містить три випадки та пояснення методу.

Скорочення відкрито пояснено у вступі та біля відповідних таблиць: EPA, PMSM, NMC/LFP, WLTP/WLTC, PER, UBE, CSS та інші. Електричний опір записано як R з малим індексом int; номер повторення WLTC теж має індекс. Формула втрат мотора показує три фазні мідні втрати й квадратичні втрати обертання з визначенням усіх символів. Діаграми мають повні назви величин із символами; основні абзаци вирівняні за шириною.

I-96 має кнопки **400 В** і **800 В**, а також власне числове введення. Кнопки узгоджують I-95–98, зберігаючи енергію, опір і струмові межі. 400 В залишається початковим припущенням; вибір 800 В сам по собі не збільшує енергію батареї.

### Термінологія 720°
Для чотиритактного ДВЗ використовується термін **«розгорнута індикаторна діаграма p–θ, 0–720° ПКВ»**. «720°» означає повний робочий цикл за кутом повороту колінчастого вала, а не «розширений» формат графіка.


## WLTC та критерій завершення BEV (1 жовтня 2026)

У розділі 8 виберіть I-120: Class 3a, Class 3b або автовибір. I-192 задає максимальну швидкість до окремого обмежувача; I-197/198 задають додатковий cap. I-193 перемикає заданий резерв SOC або втрату швидкості протягом 4 с. Деталі й припущення: `docs/WLTP-OPTIONS-2026-10-01.md`.

Для перевірки відкрийте через кнопку «Відкрити проєкт JSON» один із файлів:

- `build/BEV-130kW-Class3a-SOC-project.json`
- `build/BEV-130kW-Class3a-performance-project.json`
- `build/BEV-130kW-Class3b-performance-project.json`

Відповідні звіти, аркуші A1 та CSV знаходяться поруч у `build`. A1 окремо підписує критерій завершення та два результати процедури; резервний проєктний пробіг залишається в основній таблиці.

Перевірки: `bash run.sh --check`; окрема швидка перевірка WLTP: `node build/test-wltp-options.cjs`. Після зміни вихідного коду: `bash run.sh --html-only`. Для відтворення збережених EV/PHEV прикладів: `node scripts/export-saved-projects.mjs` (HTML/CSV/JSON). Для повторного PDF-експорту цих прикладів за наявності Chrome/Chromium: `node scripts/export-pdf.mjs --saved`. Поточний HTML також можна відкрити й надрукувати в PDF з браузера.
